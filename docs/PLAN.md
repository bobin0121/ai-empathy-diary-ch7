# AI 공감 다이어리 작업 계획

오늘 있었던 일을 한 줄로 쓰면 AI가 감정을 분석하고 공감하며 위로해 주는 일기 앱을, `.claude/agents`의 에이전트 5개로 단계별로 만든다. 사용자가 "계획의 N단계를 진행해줘."라고 할 때만 그 단계를 진행한다.

## 요구 사항 요약 (5W1H)

| 항목 | 내용 |
|---|---|
| 누가 | 구글 계정으로 로그인한 사용자. 로그인은 Auth.js. 사용자는 자기 일기만 본다 |
| 무엇을 | 한 줄 일기 쓰기, 감정 분석과 공감 메시지, 지난 기록 보기. 위기 표현(자해, 극단적 선택 등)이 있으면 공감 메시지와 함께 전문 상담 연락처 안내 |
| 어떻게 | Next.js. 일기는 `.env`의 `DATABASE_URL`이 가리키는 Supabase Postgres에 `diary` 스키마를 새로 만들어 저장. 다른 스키마의 표는 건드리지 않음 |
| AI 모델 | OpenRouter `nvidia/nemotron-3-ultra-550b-a55b:free`를 먼저 부르고, 응답이 없거나 오류면 `nvidia/nemotron-3.5-super-vl:free`로 넘어감. 키는 `.env`의 `OPENROUTER_API_KEY` (두 모델 모두 2026-11-12 무료 목록에 있음을 확인) |
| 어디에 | 깃허브 `ai-empathy-diary-ch7`, Vercel 배포 |
| 느낌 | 따뜻하고 편안한 일기장 화면 |

## 단계

| 단계 | 할 일 | 맡는 에이전트 | 산출물 | 끝났는지 확인하는 법 |
|---|---|---|---|---|
| 0단계 PRD | 목표, 기능(F 번호), 사용자 시나리오, 화면 명세, 범위 밖, 결정 사항 정리 | product-manager | `docs/PRD.md` | PRD에 필수 기능 표와 범위 밖 줄이 있고, 사용자가 승인함 |
| 1단계 뼈대 | Next.js 프로젝트 생성, 폴더 구조, 공용 타입과 API 약속(요청과 응답 형식), 환경 변수 이름 목록(`.env.example`), 빈 페이지 | backend-developer | 실행되는 빈 앱, `docs/API.md` | `npm run build`가 통과하고 `npm run dev`로 첫 화면이 뜸 |
| 2단계 동시 진행 | 아래 세 트랙을 동시에. 맡은 폴더만 고쳐 서로 덮어쓰지 않음 | 아래 표 | 트랙별 코드 | 트랙마다 빌드 통과, 트랙별 확인 항목 통과 |
| 3단계 통합 | 세 트랙을 잇기, 구글 로그인(Auth.js) 연결, `diary` 스키마에 저장과 조회, 위기 안내 연결 | backend-developer, frontend-developer | 처음부터 끝까지 도는 앱 | 내 컴퓨터에서 구글 로그인 → 일기 쓰기 → 감정과 공감 → 지난 기록 → 다른 계정으로는 내 일기가 안 보임 |
| 4단계 QA | PRD 기능별 시험, 오류 처리(빈 입력, 긴 입력, 로그인 없이 접근, 모델 실패, DB 실패), 보안 점검 | qa-engineer (haiku, 같은 코드를 opus로도 견줌) | QA 보고서 `docs/QA.md` | 높음 항목이 0건이거나 고친 뒤 다시 시험해 통과 |
| 5단계 배포 | Vercel 배포, 환경 변수 등록, 구글 OAuth 리디렉션 주소 등록 | backend-developer (설정은 사용자가 직접) | 배포 주소 | 배포 주소에서 3단계 확인 흐름이 그대로 됨 |

### 2단계 세 트랙

| 트랙 | 맡는 에이전트 | 맡는 폴더(예정) | 확인 항목 |
|---|---|---|---|
| 백엔드 | backend-developer | `app/api/`, `lib/db/`, `db/` (스키마 SQL) | `diary` 스키마 생성 SQL, 일기 저장과 조회 API가 시험 요청에 응답 |
| AI | ai-integration-specialist | `lib/ai/` | 감정 분석과 공감 메시지 JSON을 돌려줌, 첫 모델 실패 시 두 번째 모델로 넘어감, 위기 표현 감지 |
| 화면 | frontend-developer | `app/(pages)/`, `components/` | 일기 쓰기, 결과, 지난 기록 화면이 가짜 데이터로 그려짐, 375px 폭에서 깨지지 않음 |

## 0단계에서 정할 것

- 일기 수정과 삭제를 넣을지, 넣으면 범위
- 감정 분류의 종류(예: 기쁨, 슬픔, 분노, 불안, 평온 등)
- 무료 모델이 실패했을 때 사용자에게 보여 줄 안내
- 위기 표현 감지 방식(키워드, AI 판단, 둘 다)과 안내할 상담 연락처
- 구글 OAuth 클라이언트(7.4.8항에서 새로 만듦)
- 하루에 일기를 몇 개까지 쓸 수 있는지
