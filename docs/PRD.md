# AI 공감 다이어리 PRD

작성: product-manager, 0단계. 사용자 승인 전까지는 초안이다.

## 1. 제품 개요

### 1.1 제품 목표

오늘 있었던 일을 한 줄로 쓰면, AI가 그 글에서 주된 감정과 강도를 읽어 내고 따뜻한 공감 메시지를 돌려주는 일기 앱이다. 쓰는 부담은 한 줄로 낮추고, 쓰고 나면 누군가 들어 준 느낌을 주는 것이 목표다. 지난 기록을 모아 보면 요즘 마음이 어땠는지 돌아볼 수 있다.

### 1.2 대상 사용자

- 구글 계정이 있고, 길게 쓰기는 부담스럽지만 하루를 짧게 남기고 싶은 사람.
- 주로 휴대폰(폭 375px)에서 쓴다. 컴퓨터 화면에서도 쓸 수 있어야 한다.
- 사용자는 자기 일기만 볼 수 있다.

### 1.3 성공 기준

| 번호 | 기준 | 확인 방법 |
|---|---|---|
| S1 | 구글 로그인부터 일기 저장, 감정과 공감 메시지 확인까지 한 번에 끝난다. | 3단계 통합 시험 |
| S2 | 일기 제출 후 결과 화면에 공감 메시지가 나올 때까지 보통 10초 안쪽이다. 길어지면 로딩 문구가 보인다. | 4단계 QA |
| S3 | 다른 계정으로는 내 일기가 조회, 삭제되지 않는다. | 4단계 QA 보안 점검 |
| S4 | 위기 표현이 들어간 일기는 AI 성공 여부와 무관하게 상담 연락처 안내가 나온다. | 4단계 QA, 모델 실패 상태에서도 시험 |
| S5 | 두 무료 모델이 모두 실패해도 일기 본문은 저장되고, 사용자가 다시 분석할 수 있다. | 4단계 QA |
| S6 | 375px 폭에서 가로 스크롤이 생기지 않고 모든 단추를 누를 수 있다. | 4단계 QA |
| S7 | 운영 비용이 0원이다. | 무료 모델과 무료 요금제만 사용, 5단계 배포 점검 |

## 2. 기술 구성

| 영역 | 선택 | 비고 |
|---|---|---|
| 웹 프레임워크 | Next.js (App Router) | 화면과 API 경로(`app/api/`)를 한 프로젝트에서 처리 |
| 로그인 | Auth.js, 구글 로그인 | 세션은 토큰(JWT) 방식. 별도 어댑터와 Auth.js 전용 표는 만들지 않는다. |
| 데이터베이스 | Supabase Postgres, `DATABASE_URL`이 가리키는 데이터베이스의 `diary` 스키마 | `diary` 스키마를 새로 만들고, 다른 스키마의 표는 읽지도 고치지도 않는다. |
| AI | OpenRouter 무료 모델. 1순위 `nvidia/nemotron-3-ultra-550b-a55b:free`, 응답이 없거나 오류면 2순위 `nvidia/nemotron-3.5-super-vl:free` | 두 모델 모두 2026-11-12 무료 목록에서 확인됨. 유료 모델은 쓰지 않는다. |
| 배포 | Vercel, 저장소 `ai-empathy-diary-ch7`(공개) | 공개 저장소이므로 비밀값은 절대 커밋하지 않는다. |
| 비용 | 0원 | 무료 모델, Vercel 무료 요금제, Supabase 무료 요금제 |

### 2.1 환경 변수 (이름만 적는다)

| 이름 | 용도 |
|---|---|
| `AUTH_GOOGLE_ID` | 구글 OAuth 클라이언트 ID |
| `AUTH_GOOGLE_SECRET` | 구글 OAuth 클라이언트 비밀값 |
| `AUTH_SECRET` | Auth.js 세션 서명용 비밀값 |
| `DATABASE_URL` | Supabase Postgres 연결 주소 |
| `OPENROUTER_API_KEY` | OpenRouter 호출 키 |

- 구글 OAuth 클라이언트 값은 아직 없다. 3단계 통합 때 새로 만들고, 5단계 배포 때 배포 주소의 리디렉션 주소를 추가로 등록한다(설정은 사용자가 직접 한다).
- `.env`는 열거나 출력하지 않는다. `.env.example`에는 이름만 두고 값은 비운다.

## 3. 사용자 시나리오

### 3.1 기본 흐름

1. 처음 방문: 로그인하지 않은 사용자가 주소로 들어오면 시작 화면이 보인다. 앱 소개 한 줄과 "구글로 시작하기" 단추가 있다.
2. 로그인: 단추를 누르면 구글 계정 선택 화면으로 갔다가 돌아온다. 돌아오면 일기 쓰기 화면이 열린다.
3. 일기 쓰기: 오늘의 한 줄(최대 200자)을 쓰고 "기록하기"를 누른다. 로딩 문구가 보인다.
4. 결과: 주 감정, 강도(1~5), 공감 메시지가 나온다. "새 일기 쓰기"와 "지난 기록 보기" 단추가 있다.
5. 지난 기록: 최근 것이 위에 오는 목록에서 날짜, 일기 한 줄, 감정, 공감 메시지를 본다.
6. 삭제: 일기 하나의 "삭제"를 누르면 확인 창이 뜨고, "삭제하기"를 누르면 그 일기가 사라진다.
7. 로그아웃: 위쪽의 "로그아웃"을 누르면 시작 화면으로 돌아간다.

### 3.2 위기 표현 시나리오

1. 사용자가 자해, 극단적 선택을 떠올리게 하는 표현이 든 일기를 쓰고 "기록하기"를 누른다.
2. 서버가 키워드 검사를 먼저 한다. 걸리면 위기 표시를 켠다. AI 분석도 같이 돌려, AI가 위기라고 판단해도 위기 표시를 켠다. 둘 중 하나라도 위기면 위기다.
3. 결과 화면에 공감 메시지와 함께 상담 연락처 카드(3.4항, 8.2항)가 공감 메시지 위에 눈에 띄게 나온다.
4. AI가 둘 다 실패해도 키워드에 걸렸으면 연락처 카드는 반드시 나온다. 이때 공감 메시지 자리에는 AI 실패 안내와 함께 짧은 고정 위로 문구가 들어간다.
5. 지난 기록에서도 위기 표시가 켜진 일기에는 연락처 카드를 다시 볼 수 있는 "도움 받을 곳" 단추가 있다.

### 3.3 AI 실패 시나리오

1. 1순위 모델이 응답이 없거나 오류를 내면 2순위 모델로 넘어간다(사용자는 모른다).
2. 2순위도 실패하면 일기 본문은 먼저 저장되어 있다. 결과 화면에 "지금은 AI 응답을 받지 못했어요. 잠시 뒤 다시 분석해 주세요."와 "다시 분석하기" 단추가 나온다.
3. 사용자가 "다시 분석하기"를 누르면 같은 일기로 분석만 다시 요청한다. 성공하면 감정과 공감 메시지가 채워진다.
4. 지난 기록에서도 분석이 안 된 일기에는 같은 안내와 "다시 분석하기" 단추가 나온다.

## 4. 화면 명세

### 4.1 공통

- 느낌: 따뜻한 종이 같은 바탕(크림색 계열), 부드러운 모서리, 손글씨 느낌이 나는 제목 글꼴 가능(무료 글꼴), 본문은 읽기 편한 고딕. 감정마다 은은한 색과 이모지를 붙인다.
- 폭: 375px 기준으로 설계한다. 한 칸 세로 배치, 좌우 여백 16px, 가로 스크롤 없음. 넓은 화면에서는 가운데 정렬로 최대 폭 640px.
- 접근성: 글자 크기 16px 이상, 단추 누르는 영역 최소 44px, 본문과 바탕의 명암비 4.5:1 이상, 모든 입력과 단추에 이름(레이블), 키보드로 이동과 실행 가능, 눈에 보이는 초점 표시, 로딩과 오류 문구는 화면 낭독기가 읽도록 `aria-live` 지정, 감정은 색만이 아니라 글자와 이모지로도 표시.
- 상단 줄(로그인 후): 왼쪽에 앱 이름 "공감 다이어리", 오른쪽에 "로그아웃". 아래에 두 탭 "쓰기", "지난 기록".
- 문구는 완결된 문장이면 마침표로 끝내고, 단추 이름과 제목에는 마침표를 붙이지 않는다.

### 4.2 감정 분류 (확정)

| 감정 | 이모지 | 설명 |
|---|---|---|
| 기쁨 | 😊 | 즐겁고 뿌듯하고 감사한 마음 |
| 슬픔 | 😢 | 속상하고 외롭고 그리운 마음 |
| 분노 | 😠 | 화나고 억울하고 짜증 나는 마음 |
| 불안 | 😰 | 걱정되고 초조하고 두려운 마음 |
| 평온 | 😌 | 차분하고 편안하고 무난한 마음 |
| 지침 | 😮‍💨 | 피곤하고 힘이 빠지고 번아웃 같은 마음 |

- 일기마다 위 6가지 중 하나를 주 감정으로 고르고, 강도는 1(약함)부터 5(매우 강함)까지의 정수로 정한다. 목록 밖의 값은 허용하지 않는다.
- 강도 표시: ● 개수 또는 "강도 3/5" 글자로 함께 보여 준다.

### 4.4 일기 쓰기 화면 (`/write`)

| 요소 | 내용 |
|---|---|
| 제목 | 오늘은 어땠나요? |
| 입력 | 한 줄 입력칸, 안내 글자(placeholder) "오늘 있었던 일을 한 줄로 적어 보세요." |
| 글자 수 | 입력칸 아래에 "37/200" 형식으로 표시. 200자를 넘기지 못하게 막는다. |
| 단추 | 기록하기 |
| 줄바꿈 | 한 줄 입력이므로 줄바꿈은 공백으로 바꿔 저장한다. |
| 빈 상태 | 입력이 비었거나 공백뿐이면 "기록하기"가 비활성이고 눌러 볼 수 있는 경우 "한 줄을 적어 주세요."가 보인다. |
| 로딩 상태 | 단추가 비활성이 되고 "마음을 읽고 있어요…"가 보인다. 10초가 넘으면 "조금만 더 기다려 주세요."로 바뀐다. |
| 오류 상태 | 저장 실패: "일기를 저장하지 못했어요. 잠시 뒤 다시 시도해 주세요." (입력한 글은 지우지 않는다.) 로그인 만료: "로그인이 끝났어요. 다시 로그인해 주세요." 후 시작 화면으로 이동. |

### 4.5 결과 화면 (`/result/[id]`)

| 요소 | 내용 |
|---|---|
| 일기 본문 | 방금 쓴 한 줄을 인용 상자로 보여 준다. |
| 감정 표시 | 이모지, 감정 이름, 강도 (예: "😢 슬픔, 강도 3/5") |
| 공감 메시지 | 2~3문장의 따뜻한 말 (한국어, 판단하거나 훈계하지 않음) |
| 위기 카드 | 위기 표시가 켜져 있으면 공감 메시지 위에 표시. 문구: "많이 힘드시군요. 혼자 견디지 않으셔도 괜찮아요. 지금 이야기를 나눌 수 있는 곳이에요." 아래에 3.4항 연락처 4줄. 번호는 누르면 전화가 걸리는 링크(`tel:`). |
| 단추 | 새 일기 쓰기, 지난 기록 보기 |
| 로딩 상태 | 분석이 아직 끝나지 않았으면 감정 자리에 "마음을 읽고 있어요…" |
| AI 실패 상태 | 감정, 공감 메시지 자리에 "지금은 AI 응답을 받지 못했어요. 잠시 뒤 다시 분석해 주세요."와 "다시 분석하기" 단추. 일기 본문은 저장되었다고 "일기는 안전하게 저장되었어요."를 함께 보인다. 위기 표시가 켜져 있으면 위기 카드는 그대로 나온다. |
| 오류 상태 | 일기를 찾을 수 없거나 내 것이 아니면 "일기를 찾을 수 없어요."와 "지난 기록 보기" 단추 |

### 4.6 지난 기록 화면 (`/history`)

| 요소 | 내용 |
|---|---|
| 제목 | 지난 기록 |
| 목록 | 최근 것이 위. 카드마다 날짜와 시각(한국 시각), 일기 한 줄, 감정 이모지와 이름과 강도, 공감 메시지. 한 번에 20개를 보이고 "더 보기" 단추로 다음 20개를 불러온다. |
| 카드 단추 | 삭제. 위기 표시가 켜진 일기에는 "도움 받을 곳" 단추도 있다. 분석 안 된 일기에는 "다시 분석하기"도 있다. |
| 삭제 확인 | 확인 창: 제목 "이 일기를 삭제할까요?", 설명 "삭제하면 되돌릴 수 없어요.", 단추 "삭제하기", "취소". Esc 키로 취소. |
| 삭제 후 | 목록에서 바로 사라지고 "일기를 삭제했어요."를 잠시 보인다. |
| 빈 상태 | "아직 쓴 일기가 없어요. 오늘의 한 줄을 남겨 볼까요?"와 "일기 쓰러 가기" 단추 |
| 로딩 상태 | 카드 모양의 흐릿한 자리 표시 3개와 "기록을 불러오는 중이에요." |
| 오류 상태 | 불러오기 실패: "기록을 불러오지 못했어요."와 "다시 불러오기" 단추. 삭제 실패: "삭제하지 못했어요. 잠시 뒤 다시 시도해 주세요." |

### 4.7 로그인 필요 화면 접근

로그인하지 않고 `/write`, `/result/...`, `/history`로 들어오면 시작 화면으로 보낸다. API는 401을 돌려준다.

## 5. 기능 요구 사항

### 5.1 우선순위 한눈에 보기

| 번호 | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| F1 | 구글 로그인 | 필수 | Auth.js 구글 로그인, 로그아웃, 로그인 없이는 앱 사용 불가 |
| F2 | 한 줄 일기 | 필수 | 최대 200자 한 줄 쓰기와 저장, 하루 개수 제한 없음 |
| F3 | 감정 분석과 공감 | 필수 | 6가지 감정 중 주 감정과 강도(1~5), 공감 메시지. 모델 두 개 순서대로, 둘 다 실패하면 안내와 다시 분석하기 |
| F4 | 지난 기록 | 필수 | 내 일기를 최근 것부터 목록으로 보기 |
| F5 | 위기 안내 | 필수 | 키워드 검사와 AI 판단을 함께 사용, 위기면 상담 연락처 안내. 키워드에 걸리면 AI 실패와 무관하게 안내 |
| F6 | 내 일기만 보기 | 필수 | 조회, 삭제, 다시 분석 모두 본인 일기에만 가능 |
| F7 | 일기 삭제 | 필수 | 본인 일기만, 삭제 전 확인 |
| 범위 밖 | 일기 수정, 일기 공유, 통계 대시보드, 알림(푸시, 이메일), 검색과 필터, 사진 첨부, 여러 줄 긴 일기, 다른 로그인 방식(이메일, 카카오 등), 다국어, 하루 개수 제한, 유료 모델 사용, 관리자 화면 | 하지 않음 |

### 5.2 기능별 받아들임 기준

#### F1 구글 로그인

- 로그인하지 않은 사용자가 `/write`, `/history`, `/result/...`에 들어가면 시작 화면으로 이동한다.
- "구글로 시작하기"를 누르면 구글 로그인 후 `/write`로 돌아온다.
- 로그인 후 상단에 "로그아웃"이 보이고, 누르면 세션이 끝나고 시작 화면으로 간다. 로그아웃 후 뒤로 가기를 해도 일기가 보이지 않는다.
- 로그인한 사용자의 구분 값은 구글 계정 고유 식별자다(이메일이 바뀌어도 같은 사람으로 본다).
- 로그인 취소나 실패 시 시작 화면에 오류 문구가 보인다.

#### F2 한 줄 일기

- 1자 이상 200자 이하만 저장된다. 앞뒤 공백은 지우고, 공백뿐이면 저장하지 않는다.
- 줄바꿈은 공백으로 바꾼다. 200자를 넘기는 요청은 서버가 400으로 거부한다(화면 입력 제한을 우회해도 마찬가지).
- 하루에 몇 개를 써도 된다. 개수 제한은 없다.
- 저장 실패 시 입력한 글이 남아 있고 오류 문구가 보인다.
- 저장 시각은 서버가 정한다(한국 시각으로 표시).

#### F3 감정 분석과 공감

- 일기 저장 직후 분석을 요청한다. 분석 결과는 주 감정(6가지 중 하나), 강도(1~5), 공감 메시지(한국어 2~3문장), AI의 위기 판단이다.
- 1순위 모델이 시간 안에 응답하지 않거나 오류거나 형식이 맞지 않으면 2순위 모델로 한 번 더 시도한다. 시간 제한은 모델마다 15초로 하되, 구현 단계에서 Vercel 무료 요금제의 함수 시간 한도에 맞춰 조정한다(결정 필요: 구현 시 확인).
- 감정이 목록 밖이거나 강도가 1~5가 아니면 실패로 보고 다음 모델로 넘어간다.
- 두 모델이 모두 실패하면 일기는 저장된 채 `ai_status`가 `failed`가 되고, "지금은 AI 응답을 받지 못했어요. 잠시 뒤 다시 분석해 주세요."가 보이며, "다시 분석하기"를 누르면 분석만 다시 요청한다.
- 다시 분석하기에 성공하면 감정, 강도, 공감 메시지가 채워지고 `ai_status`가 `done`이 된다.
- 공감 메시지는 조언을 강요하거나 일기 내용을 평가하지 않고, 의학적 진단을 하지 않는다(AI에게 주는 지침으로 구현 단계에서 반영).
- 사용한 모델 이름을 일기 행에 기록한다.

#### F4 지난 기록

- 내 일기만 최근 것부터 20개씩 보인다. "더 보기"로 다음 20개를 불러온다.
- 각 카드에 날짜, 한 줄, 감정, 강도, 공감 메시지가 보인다. 분석이 안 된 일기는 안내 문구와 "다시 분석하기"가 보인다.
- 일기가 없으면 빈 상태 문구가 보인다.
- 로딩과 오류 상태 문구가 4.6항대로 나온다.

#### F5 위기 안내

- 키워드 검사: 서버가 일기 본문에서 위기 표현(예: 자살, 죽고 싶, 죽어 버리, 죽을래, 목숨을 끊, 자해, 손목을 긋, 사라지고 싶, 살기 싫 등)을 찾는다. 정확한 키워드 목록은 `lib/ai/`에 두고 구현 단계에서 확정하며, 띄어쓰기 변형(예: "죽고 싶다", "죽고싶다")도 잡는다.
- AI 판단: 감정 분석 응답에 위기 여부(참/거짓)를 함께 받는다.
- 둘 중 하나라도 참이면 일기의 `crisis`가 참이 되고, 결과 화면에 위기 카드(3.4항 연락처 4개)가 나온다.
- 키워드에 걸린 일기는 AI가 두 모델 모두 실패해도 위기 카드가 나온다.
- 한 번 참이 된 `crisis`는 다시 분석해도 거짓으로 돌아가지 않는다.
- 위기 카드의 번호는 누르면 전화가 걸린다(`tel:`).
- 키워드 검사는 본문 전체에서 하며, 오탐(예: "배고파 죽겠다")이 있을 수 있음을 인정한다. 오탐은 안내가 한 번 더 나오는 정도로 두고, 안전 쪽으로 기운다.
- 위기 카드는 AI가 만든 문구가 아니라 앱에 고정된 문구와 번호를 쓴다(번호가 AI 출력에 따라 틀리지 않도록).

#### F6 내 일기만 보기

- 조회, 삭제, 다시 분석의 모든 요청은 서버가 세션의 사용자 식별자와 일기의 `user_id`를 비교한다.
- 다른 사람의 일기 번호로 요청하면 404를 돌려준다(존재 여부를 알려 주지 않는다).
- 로그인하지 않은 API 요청은 401을 돌려준다.
- 사용자 식별자는 요청 본문이 아니라 세션에서만 얻는다.
- 다른 구글 계정으로 로그인하면 내 일기가 목록에 나오지 않는다.

#### F7 일기 삭제

- 지난 기록의 카드에서 "삭제"를 누르면 확인 창이 뜬다. "삭제하기"를 눌러야만 삭제된다. "취소"나 Esc는 아무 일도 하지 않는다.
- 본인 일기만 삭제된다. 삭제는 데이터베이스에서 실제로 지운다(복구 불가).
- 삭제 성공 시 목록에서 사라지고 "일기를 삭제했어요."가 보인다. 실패하면 오류 문구가 보이고 목록은 그대로다.
- 이미 삭제된 일기를 다시 삭제하려 하면 404다.

## 6. 데이터 모델

데이터베이스는 `DATABASE_URL`이 가리키는 Supabase Postgres다. 스키마 `diary`를 새로 만들고, 그 안의 표만 다룬다. `public` 등 다른 스키마는 읽지도 고치지도 않는다. 스키마 생성 SQL은 `db/`에 둔다(`CREATE SCHEMA IF NOT EXISTS diary` 방식, 다시 실행해도 안전하게).

### 6.1 표 `diary.entries`

| 열 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `id` | uuid | 예 | 기본키, 자동 생성(`gen_random_uuid()`) |
| `user_id` | text | 예 | 구글 계정 고유 식별자(Auth.js 세션의 사용자 식별자). 인덱스 있음 |
| `content` | text | 예 | 일기 한 줄. 1~200자 검사 제약 |
| `emotion` | text | 아니오 | 기쁨, 슬픔, 분노, 불안, 평온, 지침 중 하나. 분석 전과 실패 시 비어 있음. 검사 제약 |
| `intensity` | smallint | 아니오 | 1~5. 검사 제약. `emotion`과 함께 채워지거나 함께 비어 있음 |
| `empathy_message` | text | 아니오 | 공감 메시지. 분석 전과 실패 시 비어 있음 |
| `crisis` | boolean | 예 | 위기 표시, 기본값 거짓 |
| `ai_status` | text | 예 | `done`(분석 성공), `failed`(두 모델 모두 실패). 기본값 `failed`로 두고 성공 시 `done`으로 바꾼다. 검사 제약 |
| `model_used` | text | 아니오 | 분석에 성공한 모델 이름 |
| `created_at` | timestamptz | 예 | 기본값 현재 시각 |
| `analyzed_at` | timestamptz | 아니오 | 분석 성공 시각 |

- 인덱스: (`user_id`, `created_at` 내림차순). 목록 조회에 쓴다.
- 사용자 표는 만들지 않는다(결정). 사용자 정보는 세션에만 있고 이메일, 이름은 데이터베이스에 저장하지 않는다.
- 일기 본문은 개인정보이므로 다른 곳에 복사하지 않는다.
- Supabase의 행 수준 보안(RLS) 설정은 구현 단계에서 `diary.entries`에 켜고, 앱은 서버에서만 연결 주소로 접근한다. 브라우저에서 데이터베이스로 직접 접근하지 않는다.

## 7. API 약속 초안

최종 형식은 1단계의 `docs/API.md`에서 확정한다. 모든 API는 로그인이 필요하고(F1), 사용자 식별자는 세션에서만 얻는다. 응답은 JSON이다.

### 7.1 공통 오류 형식

```json
{ "error": { "code": "VALIDATION", "message": "한 줄을 적어 주세요." } }
```

| 상태 | code | 의미 |
|---|---|---|
| 400 | `VALIDATION` | 본문이 비었거나 200자 초과 등 |
| 401 | `UNAUTHORIZED` | 로그인하지 않음 |
| 404 | `NOT_FOUND` | 일기가 없거나 내 것이 아님 |
| 500 | `SERVER_ERROR` | 서버나 데이터베이스 오류 |

AI 분석 실패는 오류 상태가 아니라 정상 응답(200, 201)의 `aiStatus: "failed"`로 알린다(일기가 이미 저장되었기 때문이다).

### 7.2 `POST /api/entries` 일기 저장과 분석

- 요청: `{ "content": "오늘 발표가 잘 끝나서 후련했다." }`
- 처리: 검증, 저장, 키워드 검사, AI 분석, 결과 반영 순서.
- 응답 201(분석 성공): 

```json
{
  "entry": {
    "id": "uuid",
    "content": "오늘 발표가 잘 끝나서 후련했다.",
    "emotion": "기쁨",
    "intensity": 4,
    "empathyMessage": "정말 애쓴 만큼 후련함이 크셨겠어요. …",
    "crisis": false,
    "aiStatus": "done",
    "createdAt": "2026-11-12T03:30:00.000Z"
  }
}
```

- 응답 201(분석 실패): 같은 모양이고 `emotion`, `intensity`, `empathyMessage`는 `null`, `aiStatus`는 `"failed"`. `crisis`는 키워드 검사 결과를 반영한다.
- 오류: 400, 401, 500(저장 자체가 실패한 경우).

### 7.3 `GET /api/entries?cursor=...` 내 일기 목록

- 요청: 쿼리 `cursor`(선택, 이전 응답의 `nextCursor`). 한 번에 20개.
- 응답 200: `{ "entries": [ {위 entry 모양} ], "nextCursor": "문자열 또는 null" }`. 최근 것부터. 내 일기만.
- 오류: 401, 500.

### 7.4 `GET /api/entries/{id}` 일기 하나

- 응답 200: `{ "entry": {...} }`
- 오류: 401, 404, 500.

### 7.5 `POST /api/entries/{id}/analyze` 다시 분석

- 요청: 본문 없음.
- 처리: 내 일기인지 확인, AI 분석만 다시 수행. `crisis`는 거짓으로 되돌리지 않는다.
- 응답 200: `{ "entry": {...} }` (성공이면 `aiStatus: "done"`, 또 실패면 `"failed"`).
- 오류: 401, 404, 500.

### 7.6 `DELETE /api/entries/{id}` 일기 삭제

- 응답 200: `{ "ok": true }`
- 오류: 401, 404, 500.

### 7.7 인증 경로

`/api/auth/*`는 Auth.js가 제공하는 경로를 그대로 쓴다.

## 8. 보안과 개인정보

### 8.1 원칙

- 본인 데이터만: 모든 조회, 삭제, 다시 분석에서 서버가 세션의 사용자 식별자로 `user_id`를 걸러 낸다. 화면에서 숨기는 것으로 대신하지 않는다.
- 키는 환경 변수로만: `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET`, `DATABASE_URL`, `OPENROUTER_API_KEY`는 코드, 문서, 로그, 저장소에 값을 적지 않는다. `.env`는 `.gitignore`에 넣는다. 저장소가 공개이므로 한 번이라도 값이 커밋되면 즉시 키를 새로 발급한다.
- 로그에 일기 본문을 남기지 않는다: 서버 로그, 오류 보고에는 일기 번호와 상태 코드만 쓰고, `content`, `empathy_message`, AI에 보낸 요청과 응답 본문은 출력하지 않는다.
- 브라우저에서 데이터베이스나 OpenRouter를 직접 부르지 않는다. 모두 서버(API 경로)에서 부른다. `NEXT_PUBLIC_` 접두어를 비밀값에 쓰지 않는다.
- SQL은 값을 따로 넘기는 방식(매개변수화)으로만 쓴다.
- 입력은 서버에서 다시 검사한다(길이, 형식). AI 응답은 믿지 않고, 감정 목록과 강도 범위를 서버에서 다시 검사한다.
- 화면에 일기와 AI 응답을 그릴 때는 HTML로 해석하지 않고 글자 그대로 그린다.
- AI 호출에 사용자 이름, 이메일, 식별자를 보내지 않는다. 일기 한 줄만 보낸다.
- 사용자의 일기는 AI 학습에 쓰이지 않는 것을 보장할 수 없으므로(OpenRouter 무료 모델 제공사 정책에 따름), 시작 화면에 "일기 한 줄은 AI 분석을 위해 외부 AI 서비스로 전달돼요."를 알려 준다(결정: 이 안내를 시작 화면 아래쪽에 작게 넣는다).

### 8.2 위기 안내 문구 관리

- 상담 번호는 앱 코드 한 곳(상수)에 두고, 화면 모든 곳이 그것을 쓴다. AI가 번호를 만들어 내지 않는다.
- 번호는 사용자가 공식 누리집에서 확인한 값이다(3.4항). 변경이 생기면 사용자 확인 후 한 곳만 고친다.

### 8.3 요청 남용 방지

- 하루 개수 제한은 두지 않는다(결정). 다만 무료 모델 한도 소진을 막기 위해, 구현 단계에서 한 사용자가 짧은 시간에 연달아 보내는 요청에 간단한 속도 제한을 두는 방안을 제안한다(결정 필요: 3단계 통합 때 backend-developer가 가능한 최소 구현을 제안하고 사용자가 판단).

## 9. 결정 사항

### 9.1 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 구글 OAuth 클라이언트 | 아직 없음. 3단계에서 새로 만들고, 환경 변수 이름만 PRD에 적는다. |
| 일기 수정 | 넣지 않는다(범위 밖). |
| 일기 삭제 | 넣는다. 본인 일기만, 삭제 전 확인. |
| 무료 모델 모두 실패 | 일기는 저장하고 "지금은 AI 응답을 받지 못했어요. 잠시 뒤 다시 분석해 주세요."를 보이며 "다시 분석하기" 단추를 준다. |
| 감정 분류 | 고정 6가지(기쁨, 슬픔, 분노, 불안, 평온, 지침)에서 주 감정 하나와 강도 1~5. |
| 저장소 | `ai-empathy-diary-ch7`, 공개. |
| 위기 안내 | 공감 메시지와 함께 109, 1577-0199, 1388, 119 안내. 키워드 검사와 AI 판단을 함께 쓰고, 키워드에 걸리면 AI 실패와 무관하게 안내. |
| 일기 길이와 개수 | 한 줄, 최대 200자, 하루 개수 제한 없음. |

### 9.2 PM이 정한 세부 (사용자가 바꿀 수 있음)

- 세션은 JWT 방식, 데이터베이스에는 일기 표 하나(`diary.entries`)만 만든다. 사용자 표는 없다.
- 지난 기록은 20개씩 "더 보기".
- 삭제는 실제 삭제(복구 불가).
- 위기 표시는 한 번 켜지면 다시 분석해도 꺼지지 않는다.
- 위기 카드의 문구와 번호는 앱에 고정한다.
- 시작 화면에 외부 AI 서비스로 전달된다는 안내를 넣는다.
- 한국 시각 표시.
